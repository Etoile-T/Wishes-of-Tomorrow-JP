# ボックス名の領域超過と読み越し

旧gText_BoxはJPN/ENG制御付き8バイト。「1」なら9バイト＋EOS、「14」なら10バイト＋EOSとなり、boxNames[14][9]（データ8＋EOS）を超過する。次の名前が書かれると前の名前のEOSが消え、タイトルのStringCopyPadded等が次の名前へ読み進め、40バイトの作業領域を超過し得る。ユーザー報告の名前崩れ・画像欠落・入力不能の原因候補として、この確実な不具合を修正した。画面での因果と復旧は未確認。初期化後の壁紙設定は通常有効値へ戻すが、不正値の読み取りも防ぐ。

修正: 同じ「ボックス」をJPN_NAME_4に変更（6バイト＋最大2桁＋EOSが9バイト内）。保存構造は不変。GetBoxNamePtrで旧8バイトのデフォルト接頭辞が厳密一致した場合のみ、番号をboxIdから再構成。任意の名称はデータ8バイトを維持し、末尾だけEOSで確実に終端する。これはゲームのRAM上の名称補正であり、通常のゲーム内セーブを行うと補正名も保存される。ホスト上のユーザー.savには触れていない。範囲外の壁紙IDは表示時に既定壁紙へフォールバックし、配列外参照を防ぐ。

全14箱の境界・隣接カナリア・番号・二度目の補正の不変性・独自名称保持を実Cヘッダーのコンパイルで検証。勝敗台詞空白修正と合わせ59テスト成功。制御コードだけの変更で新規訳文はなく、yomiyasuの再翻訳レビュー対象はなし。カタログの原文・IDは維持。

実際のA操作・アイコン・箱移動・セーブ再読み込みは未検証。別の原因が残る可能性があるため、ビルド成功をボックスの実動作確認とは扱わない。
